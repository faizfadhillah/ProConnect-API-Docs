    ProConnect API v0.2

    Build the future of work on ProConnect.

    The ProConnect API is the same one our web and mobile apps use to power candidates, employers and partner recruiters across the platform. It is a REST-style API with predictable resource URLs, JSON-encoded payloads, standard HTTP response codes, and Bearer-token authentication issued through Firebase.

    Quickstart

    The ProConnect API is built on REST conventions. All requests use HTTPS, accept and return JSON, and authenticate with a Firebase Bearer token. You can be up and running in three steps.

    1. 1

      Create a ProConnect account

      Sign up at proconnectcareer.com or call POST /users with a firebase_uid and email to provision a candidate account.

    2. 2

      Get a Firebase ID token

      Authenticate the user through Firebase Auth (email/password, phone, or OAuth). The resulting ID token is what you send as Authorization: Bearer <token> on every authenticated request.

    3. 3

      Activate the session

      Call POST /auth/session/activate immediately after login to rotate the session marker and apply the post-login active account.

    Authentication

    ProConnect uses Firebase Authentication as its identity provider. The frontend exchanges credentials for a Firebase ID token, then attaches it as a Bearer token on every request to the API.

    Authorization header

    All authenticated endpoints expect the Authorization header. Public endpoints are explicitly marked with the public tag and do not require a token.

    Sessions & multi-role accounts

    A single ProConnect user can hold multiple roles concurrently — one candidate identity plus N employer identities (one per company HQ). Use POST /auth/session/activate after login and PATCH /user-role-assignments/user-accounts/active to switch the active account.

    Token storage

    Never embed a Firebase ID token in client-side code shipped to third parties. Tokens grant the bearer the full scope of the authenticated user. Refresh tokens should be stored in HTTP-only, Secure cookies or platform-secure storage. 

    Authorization: Bearer eyJhbGciOiJSUzI1NiIs...
Content-Type: application/json
Accept: application/json
    import { getAuth } from "firebase/auth";

const token = await getAuth().currentUser.getIdToken();

await fetch("/auth/session/activate", {
  method: "POST",
  headers: { Authorization: `Bearer ${token}` },
});

    Response envelope

    Every response from the ProConnect API is wrapped in a consistent envelope produced by the global BaseResponseInterceptor. This makes clients easier to write because the location of data, message and error is always the same.

    Errors

    The API uses conventional HTTP status codes to indicate the success or failure of a request. Codes in the 2xx range indicate success. 4xx codes indicate an error caused by the request (e.g. a missing parameter). 5xx codes indicate a problem on our side (rare).

    200 / 201
    OK

    The request succeeded. 201 is returned on resource creation.

    400
    Bad Request

    Validation failed. Inspect the message array for details.

    401
    Unauthorized

    The Firebase ID token is missing, expired, or invalid.

    403
    Forbidden

    The authenticated principal lacks the required RBAC role for this resource.

    404
    Not Found

    No resource exists at the supplied identifier (or it was soft-deleted).

    429
    Too Many Requests

    You are being rate-limited. Honour the Retry-After header.

    500 / 503
    Server Error

    Something on our end. We're already alerted — share the traceId with support.

    Search & pagination

    Most resources expose a uniform GET /:resource/search endpoint that supports dynamic filters, expansions, sorting and pagination. This is the recommended way to list and filter records.

    Query paramTypeDescription
    pageinteger1-based page number. Defaults to 1.
    limitintegerPage size. Defaults to 10, max varies per resource (typically 50).
    filtersdeepObjectPer-field filters, e.g. filters[company_id]=….
    sortBydeepObjectField-to-direction map, e.g. sortBy[created_at]=DESC.
    expandsstringComma-separated relations to inline (e.g. company,skills).
    isExcelbooleanWhen true, streams an XLSX file instead of JSON.
     
    GET /jobs/search
  ?page=1
  &limit=20
  &filters[company_id]=cmp_01H…
  &filters[title]=engineer
  &sortBy[created_at]=DESC
  &expands=skills,region
    {
  "items": [ /* up to limit records */ ],
  "total": 142,
  "page": 1,
  "limit": 20,
  "totalPages": 8
}

    Rate limits

    ProConnect protects the platform with two layers of throttling: a baseline per-IP limit and a per-user notification limiter for sensitive flows like OTP and password resets.

    • Default: 60 requests / minute / IP for authenticated traffic.
    • OTP: 5 OTP requests / hour / user via NotificationRateLimitGuard.
    • Bulk import: 1 active batch per company at a time.

    When throttled the API returns 429 Too Many Requests with the standard Retry-After header (in seconds). Retries should use full-jitter exponential backoff.

    Versioning

    The current API is v0.2. We follow a backward-compatible contract for additive changes (new endpoints, new optional fields). Breaking changes are announced in the changelog with a minimum 30-day deprecation window. The Swagger / OpenAPI spec served at /api on every environment is the source of truth.

    Core flows

    End-to-end recipes that compose the most common user journeys.

    Sign up & verify a candidate

    1. POST /users — Create the user record (public).
    2. POST /users/public-request-otp — Send a one-time code to the email.
    3. POST /users/verify-otp — Confirm the code; the user becomes verified.
    4. POST /auth/session/activate — Activate the session after login.

    Switch between candidate & employer accounts

    1. GET /users/me — Returns the user's accounts array (one per role/scope).
    2. PATCH /user-role-assignments/user-accounts/active — Set active_session_account_id.
    3. GET /user-role-assignments/active — Confirm the active assignment.

    Apply for a job

    1. GET /jobs/public/all — Browse published jobs (no auth).
    2. GET /jobs/public/slug/:slug — Resolve the slug from the URL.
    3. POST /applicants — Submit the application.
    4. POST /applicant-legal-files — Upload supporting documents.

    Publish a job (employer)

    1. POST /mst-companies/upsert-member — Ensure the recruiter belongs to the HQ.
    2. POST /jobs — Create the job in DRAFT.
    3. POST /job-steps — Define the application stages.
    4. PATCH /jobs/:id — Move the job to PUBLISH and schedule open/close dates.

    Webhooks

    ProConnect emits webhooks for high-signal events from email delivery and asynchronous queue jobs. Endpoints are registered through your account dashboard and signed with HMAC-SHA256.

    EventSent whenChannel
    email.deliveredMailjet confirms delivery to the inbox.Mailjet → POST /notifications/webhook/mailjet
    email.bouncedHard or soft bounce reported by the receiving MTA.Mailjet → POST /notifications/webhook/mailjet
    queue.job.failedA Bull queue job exhausts its retries.Internal — surfaced via Bull Board.
    job.openedA scheduled job auto-opens at open_at.Internal — fan-out via FCM.
    job.closedA scheduled job auto-closes at close_at.Internal — fan-out via FCM.

    SDKs & libraries

    The API is OpenAPI 3.0 compliant — generate a client for any language using the spec hosted at /api-json on each environment. We officially maintain examples for the runtimes below.

    TypeScript / Node.js

    npm install axios + the generated OpenAPI client.

    Python

    pip install httpx with the openapi-python-client generator.

    PHP / Laravel

    Use Saloon or Guzzle for transport and jane-php for typed DTOs.

    Mobile (Kotlin / Swift)

    Generate via openapi-generator-cli, paired with Firebase Auth SDK.
